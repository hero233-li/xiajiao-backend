# 目标架构与实施顺序

Java17/Spring Boot/MySQL/Flyway 模块化单体，单数据库与本地私有文件，不增加缓存/队列/微服务。领域：identity（账号认证）、learning（科目周期目录个人进度）、content（知识手册与内容发布）、practice（题库练习）、assessment（检测组卷与通过）、exams（真题成绩预测授权）、planning（计划）、archive（历史认领）、audit（审计）、files（元数据/实体生命周期）、operations（后台恢复与健康）。每个模块分 api/application/domain/infrastructure，只有有规则的对象进入 domain；只转发的接口不添加。

## 写模型和事务

用户归属来自安全上下文，客户端不能指定owner。管理员写能力在应用层及HTTP入口双重校验。已有用户行锁用于串行化本人进度/成绩/计划写入；检测答案与交卷锁 session；发布先锁 course 后 release。默认异常全部回滚；告警通过独立事务Bean提交，到期保存答案只对专用 DeadlineReached 异常保留已完成结算。重放按 user+operation+key+请求摘要匹配。

分离公共发布内容与个人状态，题目/答案历史引用 immutable revision；成绩新增 score_record_revision（基线+每次编辑快照），旧记录字段不重写；内容 draft 增 revision，兼容旧请求；管理员接口客户端可通过If-Match校验，实际前端目前没有管理编辑UI。文件 ACTIVE→DELETE_PENDING→DELETED，实体提交前写入，回滚删除；失败和崩溃恢复写独立恢复目录日志并定期对账，数据库任务记录租约、次数、下次重试及错误类别。超时检测最终判分仍在单事务，后台失败不会部分产生pass。

## 迁移策略

V1–V7 校验和保持。只新增 V8及以后：成绩修订/请求幂等/后台操作状态/草稿修订和成绩试卷身份快照。迁移保留所有稳定ID、外键、未知字段、历史payload、通过和题目引用。先记录各表数量及关键字段，再迁移，再对账。无线上导出，不连接或重建用户数据库；独立MySQL构造旧版本样本演练。V9新增非空字段不支持直接切回旧jar，回退须走数据库+文件+旧应用一致备份恢复，禁止 Flyway clean/改历史checksum。

## 顺序

1. 基线检查和保留用户差异；业务/接口/前端依赖清单。
2. 文件模块与恢复、私有授权、健康；相关MySQL检查。
3. 成绩 typed 模型、纯预测规则、repository、修订与幂等；适配前端。
4. 检测事务与组卷防线、后台追踪、查询批量化；历史/权限验证。
5. 内容版本并发、计划模板规则、应用层管理员权限、其余领域迁移。
6. 新增迁移对账/回退说明，所有后端与前端构建测试、真实HTTP和浏览器联调。
7. 删除被替代实现，更新完整交付记录。图片批改只给后续任务协议设计，运行能力不伪装已实现。
